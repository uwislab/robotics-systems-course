### 16.3 强化学习基础

#### 16.3.1 马尔可夫决策过程（MDP）

强化学习（RL）的数学框架：

$$
MDP = (\mathcal{S}, \mathcal{A}, P, R, \gamma)
$$

- $\mathcal{S}$：状态空间
- $\mathcal{A}$：动作空间
- $P(s'|s, a)$：状态转移概率
- $R(s, a)$：奖励函数
- $\gamma \in [0, 1)$：折扣因子

目标：找到策略 $\pi(a|s)$ 最大化累积奖励：

$$
\max_\pi \mathbb{E}\left[\sum_{t=0}^{\infty} \gamma^t R(s_t, a_t)\right]
$$

```bob
                    "强化学习交互循环"
                    
               "状态 s_t"
  "环境" ──────────────────────→ "智能体"
    ^                               |
    |                               |
    |          "动作 a_t"           |
    +←─────────────────────────────+
    |
    └──→ "奖励 r_t"
         "下一状态 s_{t+1}"
```

#### 16.3.2 值函数与策略梯度

两大类 RL 方法：

**基于值函数（Value-based）**：学习状态-动作值 $Q(s, a)$，选择使 $Q$ 最大的动作。

$$
Q^*(s, a) = R(s, a) + \gamma \sum_{s'} P(s'|s, a) \max_{a'} Q^*(s', a')
$$

代表算法：DQN、Double DQN、Dueling DQN

**基于策略梯度（Policy Gradient）**：直接优化策略网络参数。

$$
\nabla_\theta J(\theta) = \mathbb{E}_{\pi_\theta} \left[\nabla_\theta \log \pi_\theta(a|s) \cdot A(s, a)\right]
$$

代表算法：PPO、SAC、TD3

#### 16.4.3 Sim-to-Real 迁移

仿真中训练的策略直接部署到真实机器人通常效果不佳（Reality Gap）。常用的迁移方法：

**1. 域随机化（Domain Randomization）**

在训练时随机化仿真参数（摄擦系数、质量、视觉纹理等），使策略对不确定性具有鲁棒性。

**2. 系统辨识（System Identification）**

精确测量真实系统参数，在仿真中复现。

**3. 域适应（Domain Adaptation）**

使用对抗学习等方法使仿真特征与真实特征对齐。

#### 16.5.2 行为克隆实现

```python
import torch
import torch.nn as nn
import numpy as np

class PolicyNetwork(nn.Module):
    def __init__(self, state_dim, action_dim):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(state_dim, 256),
            nn.ReLU(),
            nn.Linear(256, 256),
            nn.ReLU(),
            nn.Linear(256, action_dim),
            nn.Tanh()  # 动作归一化到 [-1, 1]
        )
    
    def forward(self, state):
        return self.net(state)

# 训练行为克隆
def train_bc(expert_states, expert_actions, epochs=100):
    model = PolicyNetwork(state_dim=6, action_dim=2)  # [v, omega]
    optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)
    criterion = nn.MSELoss()
    
    states = torch.FloatTensor(expert_states)
    actions = torch.FloatTensor(expert_actions)
    
    for epoch in range(epochs):
        pred_actions = model(states)
        loss = criterion(pred_actions, actions)
        
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
        if epoch % 10 == 0:
            print(f"Epoch {epoch}, Loss: {loss.item():.4f}")
    
    return model
```

### 16.7 VLA 实时推理与毫秒级响应

16.6 节介绍的 VLA 可直接把视觉观测与语言指令映射为动作，但要把这类模型放进机器人的实时闭环，时延就成为决定成败的指标。本节先剖析普通 LLM 与 VLA 慢的根源，再按落地优先级给出面向毫秒级响应的工程改造路线。

核心结论可概括为一句话：普通对话 LLM 慢，根源是**自回归逐 token 解码 + 大量图像 token 预填充（prefill）**；而 VLA（Vision-Language-Action, VLA，视觉-语言-动作模型）要做到毫秒级端到端（几十至 200 ms），不能只优化 LLM，必须对**模型架构、动作输出范式、缓存、量化、硬件与分层控制**做全套改造。

> **注意**：真正低于 50 ms 的 VLA 很难用 7B 量级的大 VLM 主干直接硬跑。工程语境下的「VLA 毫秒级响应」通常指 100~200 ms；要求低于 50 ms 时，一般需要采用分层双系统（见 16.7.7 节）。

#### 16.7.1 为什么 VLA 慢：Prefill 与自回归解码双瓶颈

VLA 的典型结构为：**图像编码器 + 投影层 + LLM 主干 + 动作头（Action Head）**。时延来自两个瓶颈：

1. **Prefill 瓶颈（最致命）**：每当相机产生新图像，都要把几百至上千个图像 patch token 送入 Transformer 做一次完整前向计算。普通聊天 LLM 的输入只有文本 token，而 VLA 在每一个控制周期都要重新编码图像，prefill 属计算密集型，是端到端时延的主要来源。
2. **自回归解码瓶颈**：LLM 逐个串行生成动作 token，每一步都要访问键值缓存（KV Cache），访存量受显存带宽限制，难以并行。

> **注意**：OpenVLA、RT-2 等把动作编码为文本 token，直接复用 LLM 的自回归解码，因此天然偏慢。

#### 16.7.2 架构方案 A：一次性连续动作输出

治本的思路是**抛弃动作 token 自回归，改用一次性连续动作输出**，代表范式包括流匹配（Flow-Matching）、扩散 Transformer（DiT, Diffusion Transformer）与 ACT（Action Chunking with Transformers）。

π₀.₅、GR00T 等流匹配 VLA 不把动作变成 token，而是直接输出连续动作向量：

- 普通 LLM：`token1 -> token2 -> token3` 串行解码；
- 流匹配 VLA：一次前向（少量去噪迭代）直接输出一整段动作轨迹。

配套加速手段是**动作缓存（ActionCache）**：缓存相似场景下的中间去噪状态，画面相似时直接复用缓存，可把动作头的速度提升数倍到数十倍。

#### 16.7.3 架构方案 B：分层双系统

分层双系统（如 SP-VLA 思路）最适合机器人闭环，它让两套策略并行工作：

1. **快速直觉策略（轻量小模型或查表）**：高频运行，以毫秒级时延输出基础动作，负责稳定、重复的场景；
2. **重型 VLA（大模型）**：低频触发，仅在需要语义决策、遇到新物体或新指令时才运行。

> **提示**：机器人大部分时间不需要大模型推理，只有环境显著变化时才唤醒 VLA 重新规划。多数控制周期由轻量模型兜底，从而在整体上实现毫秒级控制响应。

#### 16.7.4 架构方案 C/D：Token 剪枝与一致性蒸馏

图像 token 过多是 prefill 的元凶，可用以下两种方式削减：

- **Token 剪枝与动态稀疏注意力**：利用空间语义重要性丢弃不重要的图像 patch，只保留与物体相关的视觉 token；或只对关键 token 计算注意力以减少浮点运算量。EcoVLA、FastV 属于这一路线。
- **一致性蒸馏（Consistency Distillation）**：流模型本需多次迭代去噪，蒸馏后 1~2 步即可得到最终动作，大幅减少迭代次数，无需完整采样链。

#### 16.7.5 量化压缩：W4A8 与动作头精度保护

VLA 的量化痛点是视觉 prefill 计算量巨大，因此不能只对 LLM 权重做量化。推荐 **W4A8**（权重 4 bit、激活 8 bit）方案：

- 权重 4 bit，采用 AWQ、ParoQuant 等方法；
- 激活 8 bit；
- **动作头对数值误差敏感，保留 BF16，不做量化**；
- KV Cache 使用 INT4/INT8 量化，以缓解显存带宽压力。

> **提示**：FlashDrive 在 RTX PRO 6000 上依靠该方案把单次推理从 716 ms 降到 151 ms，取得约 4.7 倍加速。

#### 16.7.6 推理引擎与缓存系统

这一层是工程落地的核心，包含三项关键技术。

**（1）PagedAttention 与前缀缓存（Prefix Cache）**：VLA 中的语言指令往往固定（例如「抓取物体」），这部分文本前缀的 KV 可以提前计算并缓存；每次推理只需对新图像 token 做 prefill，无需重复编码指令。

**（2）图像编码缓存与状态缓存**：相机帧率通常高于 VLA 推理帧率，相邻帧高度相似。可复用上一帧的视觉 embedding，只有当画面变化超过阈值时才重新运行视觉编码器。也就是说，**并非每帧图像都跑完整 VLA**，变化小时直接复用上次输出。

**（3）推测解码（Speculative Decoding）**：如果必须保留 LLM 自回归动作 token 范式（如 OpenVLA、RT-2），可由小草稿模型一次性预生成多个动作 token，再由大模型一次前向批量校验，一次验证多个 token，减少串行步数。该方法适合无法改动模型结构的场景。

#### 16.7.7 硬件调度、控制域与落地路线

硬件与系统层面的优化包括：

1. **本地高带宽 GPU，避免走网络**：网络往返时延（RTT）会直接吃掉几十毫秒，毫秒级 VLA 必须端侧本地推理（如 Jetson Thor、RTX 4090/5090），不能依赖远程 API。
2. **算子融合与编译优化**：使用 TensorRT-LLM、SGLang、MLC-LLM 等对 Transformer 层与视觉编码器进行算子融合，减少 GPU 核启动开销与内存读写。
3. **异步流水线推理（最重要的系统技巧）**：将相机采集、图像编码、VLA 推理、机器人执行做流水线重叠，机器人在执行上一轮动作时，VLA 已在并行处理下一帧图像，从而掩盖推理时延。其目标不是降低单次推理耗时，而是掩盖时延、使控制闭环周期达到毫秒级。

```bob

|              "分层 VLA 异步流水线（ms 级闭环）"                  |
+----------------------------------------------------------------+
|  "高频控制环（5~20 ms）"                                        |
|                                                                |
|  "相机采集" --> "图像编码" --> "轻量策略" --> "机器人执行"        |
|       |             |              ^              |            |

|  "视觉特征缓存" <----+              |        "动作执行"          |
```

控制域方面，VLA 通常一次性预测未来 N 步动作轨迹：N 越大推理越慢。做闭环控制时应**缩短动作预测窗口（horizon）**，只预测很短的一段动作并快速重规划；代价是重规划频率升高，但单步推理时延显著下降。

综合上述手段，可按需求选择两条落地路线：

- **路线 A：端到端单模型，100~200 ms（适合研究）**。推荐组合：流匹配 VLA + ActionCache + W4A8 量化 + 图像特征缓存 + Prefix Cache + TensorRT 算子编译；代表工作有 FlashDrive、π₀.₅ + ActionCache。
- **路线 B：低于 50 ms 闭环响应（工业实时控制，推荐工程方案）**。采用分层双系统：轻量快速策略以 5~20 ms 持续输出控制量，重型 VLA 作为慢速规划器以 200 ms 级低频更新参考轨迹。实时控制由轻量模型负责，VLA 只承担语义理解、新场景适应与目标切换，不参与高频控制环。SP-VLA 即这一范式，是目前兼顾毫秒级闭环与 VLA 泛化能力的可行方案。

#### 16.7.8 常见误区与落地检查清单

工程实践中常见的三个误区：

1. **只靠推测解码无法把 VLA 压到毫秒级**：VLA 最大的瓶颈是图像 prefill 而非 token 解码，推测解码只优化解码阶段，对视觉预填充几乎无效。
2. **远程 API 调用不可能达到毫秒级**：网络时延几十至上百毫秒，直接卡死时延下限，VLA 必须本地端侧 GPU 推理。
3. **把 7B VLM 直接量化到 4 bit 就期望几十毫秒**：图像 token 数量庞大、prefill 开销巨大，单纯量化并不足够，必须配合图像 token 裁剪与特征缓存。

落地时可按成本从低到高依次尝试：

1. 启用图像特征缓存：画面变化小时复用视觉 embedding（改动最小、收益高）；
2. 采用 W4A8 量化，动作头保持高精度；
3. 用 Prefix Cache 缓存固定语言指令的 KV；
4. 做 token 剪枝，减少图像 patch token 数量；
5. 换成流匹配架构并配合 ActionCache（治本，需要微调或重训模型）；
6. 采用分层双系统架构，由轻量策略接管高频实时控制。

### 16.9 实践：基于 RL 的导航策略

#### 16.9.1 环境设计

使用 Gazebo 仿真创建一个简单的避障导航环境：

```python
# 基于 ROS2 的 RL 导航环境（简化版）
import gymnasium as gym
import numpy as np

class GazeboNavEnv(gym.Env):
    """差速机器人避障导航环境"""
    
    def __init__(self):
        super().__init__()
        # 状态：[激光雷达 24 点, 目标方向, 目标距离]
        self.observation_space = gym.spaces.Box(
            low=0, high=10, shape=(26,), dtype=np.float32)
        # 动作：[线速度, 角速度]
        self.action_space = gym.spaces.Box(
            low=np.array([0.0, -1.0]),
            high=np.array([0.5, 1.0]),
            dtype=np.float32)
    
    def step(self, action):
        v, omega = action
        # 发送速度指令到 Gazebo
        self._send_cmd_vel(v, omega)
        
        # 获取新状态
        obs = self._get_observation()
        
        # 计算奖励
        reward = self._compute_reward(obs)
        
        # 判断是否结束
        terminated = self._check_collision() or self._check_goal_reached()
        
        return obs, reward, terminated, False, {}
    
    def _compute_reward(self, obs):
        """奖励函数设计"""
        min_laser = np.min(obs[:24])
        goal_dist = obs[25]
        
        reward = 0.0
        # 接近目标奖励
        reward += (self.prev_goal_dist - goal_dist) * 10.0
        # 碰撞惩罚
        if min_laser < 0.2:
            reward -= 100.0
        # 靠近障碍物惩罚
        elif min_laser < 0.5:
            reward -= 1.0
        # 到达目标奖励
        if goal_dist < 0.3:
            reward += 200.0
        
        self.prev_goal_dist = goal_dist
        return reward
```

<quiz>
2) PPO（Proximal Policy Optimization）相比原始策略梯度方法的改进是什么？
- [x] 通过裁剪（clipping）限制每次策略更新的幅度，提高训练稳定性
- [ ] 完全消除了方差，不再需要 baseline
- [ ] 可以处理离散动作空间但不能处理连续动作
- [ ] 不需要价值函数作为评价基准

PPO 用 clip(ratio, 1-ε, 1+ε) 限制新旧策略的概率比，防止单步更新过大导致策略崩溃。它仍然使用 GAE 和价值网络来降低方差，且同时支持离散和连续动作空间。

<quiz>
3) 行为克隆（Behavior Cloning）最主要的局限性是什么？
- [x] 分布偏移（covariate shift）：策略的小误差累积导致偏离专家轨迹分布
- [ ] 只能模仿人类，不能模仿其他机器人
- [ ] 需要在线与环境交互
- [ ] 无法学习连续控制策略

行为克隆将模仿学习简化为监督学习，但训练时智能体只见到专家分布内的状态。实际执行时微小的偏差会使智能体进入未见过的状态，进一步加大误差——即 covariate shift 问题。DAgger 通过在线收集专家修正数据来缓解此问题。

- [ ] LLM 只负责生成训练数据

- [ ] 动作 token 的自回归解码步数太多，与图像无关

</quiz>
